# TUFLOW Path Validator v0.2.7 — proposed release notes

**Status:** Release candidate only; not published. Final release requires explicit owner approval. No Marketplace delivery or installed-profile acceptance is claimed here.

## Changes since published v0.2.6

- **More accurate file-path diagnostics:** Use recognised input-file commands rather than guessing that arbitrary configuration values are paths. In particular, `Viscosity Formulation == SMAGORINSKY`, `Viscosity Coefficients == 0.2, 0.1` and numeric/unknown commands no longer generate false missing-file errors. Genuine missing inputs remain detectable. See [issue #10](https://github.com/Chain-Frost/tuflow_validator/issues/10).
- **Control-file dependencies and context:** Improve recursion and interpretation of actual control-file text, inline `Read File` includes, static variables and TRD editor contexts, retaining independent diagnostics for shared roots. Known data-file paths are checked for existence without treating datasets as control commands.
- **Freshness and manual refresh:** Improve diagnostic invalidation and provide **TUFLOW Path Validator: Refresh Path Diagnostics** for explicit revalidation. For network UNC/mapped projects, automatic freshness after external changes is supported only when the model directory is opened as a VS Code workspace. Individually opened network files without a workspace require manual refresh after external changes; this is an accepted limitation.
- **Compatibility and packaged output:** Retain support for VS Code **1.74 and newer**, regression tests for minimum/current VS Code on Windows/Linux, and installed coexistence with TUFLOW Helper. Package excludes test and development dependencies.
- **Release infrastructure:** Prepare manually approved Marketplace Trusted Publishing with GitHub Actions OIDC, immutable-tag checks, separate verification and production-approved publishing jobs, and verified VSIX/checksum handoff. No automatic release trigger or PAT fallback.

## Release/verification conditions

- Exact release source must be merged onto `main`, then checked for the matching new `v0.2.7` tag. The full commit SHA, verified VSIX SHA-256, package identity, compiled parser/diagnostics module hashes and Actions run must be recorded from the authorised release process; none are final at proposal stage.
- GitHub `production` reviewer gate, tag ruleset and Marketplace policy `Path Validator production` are configured; the policy currently reports `Last used: Never`. A real OIDC exchange and Marketplace publication have **not** been performed.
- After successful publication, independently obtain the Marketplace-delivered package, compare its manifest and compiled module hashes against the approved VSIX, then validate the actual normal installed VS Code profile. Leave [issue #10](https://github.com/Chain-Frost/tuflow_validator/issues/10) open until that acceptance is complete.
- Preserve existing extension identity `Chain-Frost.tuflow-path-validator`; publishing and updating TUFLOW Helper, inspecting GeoPackage contents, and model-wide parameter validation are outside this release.
